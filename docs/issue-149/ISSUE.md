# 概要
<!-- このチケットで解決したい課題 -->
git worktreeを使っていますが、worktree作成のたびにinit-devを実行する、worktree切り替えのたびに元のブランチのコンテナを停止して、次のworktreeでdevを実行する必要があるなど、運用が煩雑です。
これであれば、普通のブランチ運用で一時的なコミットを行うのと大差ないため、worktree運用のメリットが薄れています。

理想としては、コンテナは裏で動きつつ、そのソースコードが読み込むのは現在のworktreeのコード、という形が望ましいです。
つまりworktree切り替えのたびにコンテナを停止・起動する必要がなく、複数のworktreeで同時にdevサーバーが立ち上がっていても問題ない形です。

このような実装、構成変更がないか検討し、あれば実装してください
