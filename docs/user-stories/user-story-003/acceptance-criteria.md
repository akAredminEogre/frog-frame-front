# 受け入れ条件

## ユーザーストーリー要件

- [ ] AC-1: ルール一覧の各行にゴミ箱アイコンが表示される
- [ ] AC-2: ゴミ箱アイコンをクリックすると確認ダイアログが表示される
- [ ] AC-3: 確認ダイアログで「削除」を選択するとルールが削除される
- [ ] AC-4: 確認ダイアログで「キャンセル」を選択すると何も起こらない
- [ ] AC-5: 削除されたルールがルール一覧から消える
- [ ] AC-6: 削除失敗時はトースト通知でエラーメッセージが表示される

## 技術要件

- [ ] AC-7: 削除されたルールのURLパターンに一致するタブがリロードされる
- [ ] AC-8: 削除処理中は同じルールの重複削除が防止される（`deletingIds` による制御）
- [ ] AC-9: 部分的成功時（削除成功・タブリロード失敗）はルールを一覧から削除し、エラー通知を表示
- [ ] AC-10: ルールはDBから物理削除される（論理削除ではない）
- [ ] AC-11: 削除要求はmessaging経由でBackground Scriptに送信される（ADR-002, ADR-003準拠）
- [ ] AC-12: Clean Architectureの層構造が遵守されている
  - Interactorは IRewriteRuleRepository と ITabsGateway に依存（具象クラスに依存しない）
  - PresenterはReactコールバックを受け取り、Viewの状態を更新
  - Controllerは Factory 経由で生成される（ADR-005準拠）
- [ ] AC-13: make testcheck がパスする
