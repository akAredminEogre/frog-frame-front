# ADR-001: WXTフレームワークの採用

**ステータス:** 採用  
**日付:** 2025-01-01  
**決定者:** 開発チーム

## コンテキスト

Chrome拡張機能の開発において、以下の課題を解決する必要があった:

1. **開発体験の向上**: Hot Module Replacement (HMR)、TypeScript対応、ビルドプロセスの自動化
2. **マニフェスト管理**: Manifest V3への対応、動的なマニフェスト生成
3. **クロスブラウザ対応**: Chrome/Firefox等の複数ブラウザへの対応
4. **モダンな開発環境**: React、TypeScript、モジュールベースの開発への対応
5. **ボイラープレート削減**: Chrome Extension API特有の冗長なコードの削減

## 検討した選択肢

### 選択肢1: crxjs


### 選択肢3: WXT

**メリット:**
- **優れた開発体験**: HMR、自動リロード対応
- **柔軟な設計**: Clean Architectureとの親和性が高い
- **TypeScript完全対応**: 型定義が充実
- **Viteベース**: 高速なビルド、モダンな開発環境
- **defineBackground/defineContentScript等の便利なAPI**: ボイラープレート削減
- **マニフェスト自動生成**: wxt.config.tsでの一元管理


## 決定

**WXTフレームワークを採用する。**

理由:
1. **開発効率の大幅向上**: HMRとTypeScript対応により開発速度が向上
2. **Clean Architecture適用が容易**: `src/`ディレクトリ構造を自由に設計可能
3. **保守性の向上**: `wxt.config.ts`での設定一元管理、定型コードの削減
4. **本プロジェクトの要件に最適**: DOM操作を行うChrome拡張として必要な機能が全て揃っている
5. **Viteエコシステム**: プラグインや設定のカスタマイズが容易

## 影響

**ポジティブ:**
- 開発速度の向上（HMR、自動リロード）
- コードの可読性向上（ボイラープレート削減）
- TypeScript型安全性の向上
- ビルドプロセスの簡素化
- React統合が容易

**ネガティブ:**
- WXTフレームワークの学習コストが発生
- フレームワークのバージョンアップへの追従が必要
- WXTのバグや制限事項の影響を受ける可能性

**リスク:**
- WXTプロジェクトのメンテナンス停止リスク
- Breaking changesによる移行コスト
- WXT固有の問題でのトラブルシューティング難易度
