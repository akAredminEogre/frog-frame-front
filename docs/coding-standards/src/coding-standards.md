# ソースコード言語ガイドライン

## 適用シナリオ

1. **新規クラスやメソッドにJSDocを追加する場合**: 英語のJSDocテンプレートを使わず、日本語で記述する。`@example`を書きたくなった場合は、テストコードへの参照に置き換える
2. **エラーメッセージを新規作成する場合**: 開発者が読むログメッセージであっても日本語で記述する。ただしクラス名やメソッド名はそのまま英語で記載する（例: 「MyClass.setup() を呼び出す必要があります」）

## JSDoc

- 日本語で記述すること
- 文体は断定系を使うこと
  - ですます調は使わない
- `@example`は使用しない
  - コード例はコーディング規約との整合性を維持するコストが高い
  - 実装例が必要な場合はテストコードを参照すること

## エラーメッセージ・ユーザー向け文字列

- エラーメッセージは日本語で記述すること
- 例外: 技術的な識別子（クラス名、メソッド名等）は英語のまま記載可

```typescript
// ❌ 悪い例: 英語のエラーメッセージ
throw new Error('setup() must be called before using other methods.');

// ✅ 良い例: 日本語のエラーメッセージ（クラス名は英語可）
throw new Error('他のメソッドを使用する前に MyClass.setup() を呼び出す必要があります。');
```

## コメント

- インラインコメントは日本語で記述すること
- 技術用語は英語表記も許容（例: React、useEffect）
- 非自明な設計決定には理由を記載すること
  - 特にアクセシビリティ関連の決定は、準拠する規格・ベストプラクティスを明示する

### アクセシビリティ関連コメントの例

```typescript
// ❌ 悪い例: 何をしているかだけ
// 初期フォーカス設定（キャンセルボタンにフォーカス）

// ✅ 良い例: なぜその設計なのか理由を記載
// 初期フォーカス設定
// WAI-ARIAベストプラクティス: 破壊的アクションを伴うダイアログでは
// 安全な選択肢（キャンセルボタン）に初期フォーカスを設定
```
