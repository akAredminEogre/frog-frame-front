# CSS Modules 使用規約

## 概要

CSS Modules を使用する際のクラス名管理とテストセレクタの分離に関する規約。

## 規約

### 1. CSS Modules のクラス名とグローバルクラス名を混在させない

CSS Modules で定義したクラスセレクタは、必ず `styles.className` 形式で参照すること。
グローバルクラス名（文字列リテラル `"class-name"`）とCSS Modules のクラス名を同じ目的で混在させてはならない。

**理由**: CSS Modules のクラス名はビルド時にハッシュ化されるため、グローバルクラス名と対応関係がなくなる。これにより、意図したスタイルが適用されない問題が発生する。

### 2. テストセレクタには data-testid を使用する

E2E テストやユニットテストで要素を特定する場合は、`data-testid` 属性を使用すること。
CSS クラス名をテストセレクタとして使用してはならない。

**理由**: CSS クラス名はスタイリングの目的で使用されるべきであり、テストのためのセレクタとして使用すると、スタイリングの変更がテストに影響を与える（またはその逆）。

### 3. テーブル列のスタイリングには nth-child セレクタを使用する

テーブルの列ごとのスタイリングには、CSS Modules 内で `nth-child` セレクタを使用すること。
これにより、子コンポーネント（`<tr>`、`<td>`）に個別のクラス名を付与する必要がなくなる。

**理由**: 親コンポーネント（テーブル）のCSS Modules から子コンポーネント（行）のスタイルを制御でき、CSS の責務が明確になる。

## 適用シナリオ

### シナリオ1: コンポーネントにスタイルを適用したい場合

CSS Modules からインポートした `styles` オブジェクトを使用する。

### シナリオ2: E2E テストで要素を特定したい場合

`data-testid` 属性を追加する。CSS クラス名でセレクトしない。

### シナリオ3: 親コンポーネントから子コンポーネントの列にスタイルを適用したい場合

親コンポーネントの CSS Modules で `nth-child` セレクタを使用する。
子コンポーネントにグローバルクラス名を付与してスタイリングしない。

## 違反時の影響

- レスポンシブスタイルが適用されない
- スタイルの変更がテストを壊す（またはその逆）
- CSS の責務が不明確になり、メンテナンス性が低下する
