# scripts コーディング規約
## オブジェクト指向ルール（ThoughtWorksアンソロジー）

9つのルールのうち、下記3つは必ず遵守すること：

1. **1つのメソッドにつきインデントは2段階までにすること**
  - 原典では1段階までとなっているが、makeプロジェクトでは2段階まで許容する
2. **else句を使用しないこと**
  - → early returnパターンを使用すること
5. **名前を省略しないこと**

## 命名規則
- 変数名は **UPPER_CASE** （大文字スネークケース）を使用すること
  - 例: `CHECK_MODE`, `MAXIMUM_NUMBER`, `NEW_NUMBER`
  - 関数内のローカル変数も同様

## その他ルール
- if文は同様の条件判定がヘルパー変数として実装されていないか、それを再利用できないか調査すること
  - あるいは既存ロジックで同様の条件判定をしている場合、そのロジックをヘルパー変数化して再利用すること

## 構文解析・パーサー実装

特定の構文・フォーマット（Markdown、JSON、URL等）を解析するスクリプトを実装する際は、**その構文の仕様を網羅的に確認し、主要なバリエーションに対応すること**。

**理由**:
- 構文には通常、複数のバリエーション（オプション要素、省略形等）が存在する
- 一部のバリエーションのみ対応すると、誤検出・見落としが発生する

**手順**:
1. 対象構文の公式仕様または広く使われている仕様を確認
2. 主要なバリエーションを洗い出す
3. スクリプトのヘッダーコメントに対応する構文パターンを明記

**例**: Markdownリンク構文を解析する場合
- `[text](path)` - 基本形
- `[text](path#anchor)` - アンカー付き
- `[text](path "title")` - タイトル付き（ダブルクォート）
- `[text](path 'title')` - タイトル付き（シングルクォート）
