# §8 JSDocルール

## 目的

テストコードのJSDocコメントを一貫性のある形式で記述し、テストの意図を明確にする。

## ルール

### 8.1 JSDocの更新義務

テスト内容を変更した場合、JSDocコメントも必ず更新する。
実装がJSDocの説明と一致していること。

### 8.2 JSDoc記述原則

- 1ケースにつき1行でまとめる
- テストの実際の動作を正確に説明
  - 入出力値とそこから考えられるテストの目的
- 抽象的な表現を避け、具体的な検証内容を記述

### 8.3 配列ベーステストのJSDoc

配列化したテストケース群では、JSDocの各行が配列内の`description`と一致すること。
番号付きリスト形式で記述してよい。

## テスト戦略との関係

> **参照**: [05-test-strategy.md](/docs-rules/design/05-test-strategy.md)

JSDocとテスト戦略書は補完関係にある:

| JSDoc | テスト戦略書 |
| ----- | ------------ |
| 何をテストするか | なぜテストするか |
| 個別のテストケース説明 | テストケースの分類と根拠 |
| コード内のドキュメント | 設計意図と網羅性の記録 |

### 役割分担

- **JSDoc**: テストコード内で「何をテストするか」を簡潔に記述
- **テスト戦略書**: テストの全体像、分類の根拠、網羅性を記録

### 一貫性の維持

> **参照**: [§7 テスト戦略書との一貫性](./test-strategy-consistency.md)

テストケース名・順番のテスト戦略書との一致ルールは§7を参照。

## 適用範囲

- 単体テスト（unit）
- 結合テスト（integration）
- E2Eテスト（e2e）
