# ADR ドキュメントルール

## 記載方針

### 実装例は記述しない

ライブラリの変更や実装の変更があるたびに、本質的でない細かい修正が発生するため、具体的な実装コード例は記述しない。

```markdown
## 悪い例

```typescript
// 具体的なコード例
const service = getRewriteRuleService();
await service.getById(id);
```

## 良い例

サービスを定義し、他のコンテキストから透過的に呼び出す。
```

#### hooksやベースコンポーネントに切り出した場合

機能をhooksやベースコンポーネントに切り出した場合、ADRには**参照のみ**を記載する。以下の詳細はコーディング規約に委譲すること:

- コンポーネント/フックの配置パス
- 提供する機能の一覧
- 個々のhooksの用途テーブル

```markdown
## 悪い例（詳細を列挙）

#### ModalDialogBase

**配置**: `src/frameworks-and-drivers/ui/components/molecules/ModalDialogBase/`

**提供する機能**:
- ARIA属性（role, aria-modal, ...）
- フォーカストラップ
- ...

#### カスタムフック

| フック | 用途 |
|--------|------|
| useProcessingGuard | 連続クリック防止 |
| useDialogIds | ARIA用ID生成 |

## 良い例（参照のみ）

### ベースコンポーネント（推奨）

本ADRの要件を満たすベースコンポーネントとカスタムフックを提供している。
新しいダイアログコンポーネントを実装する際は、これらを使用すること。

詳細は[アクセシブルモーダルコンポーネント規約](path/to/coding-standard.md)を参照。
```

### 決定事項・判断理由のみ記述

ADR には「何を決定したか」「なぜその決定をしたか」のみを記述する。

既存設計・既存ドキュメントへの影響は記述しない。影響が発生した時点で、影響を受ける側のドキュメントを直接修正する。

```markdown
## 悪い例

### 設計への影響
- MessageHandler が不要になる
- GetByIdMessage 型が不要になる

## 良い例

（影響を受ける設計ドキュメントから該当箇所を削除する）
```

## ディレクトリ構造

```
docs/adr/
├── 001-{決定内容}.md
├── 002-{決定内容}.md
└── ...
```

## 命名規則

- 形式: `{3桁番号}-{決定内容のkebab-case}.md`
- 番号: 001から連番
- 例: `001-clean-architecture-with-presenter-pattern.md`

## 必須セクション

| セクション | 必須 | 説明 |
|-----------|------|------|
| ステータス | ○ | 採用 / 却下 / 検討中 |
| コンテキスト | ○ | 決定が必要になった背景・課題 |
| 決定 | ○ | 何を決定したか |
| 理由 | ○ | なぜその決定をしたか |
| 適用済みの箇所 | △ | 既にこのADRの要件を満たしているコンポーネント・ファイル |
| 適用待ちの箇所 | ○ | 新しい規約に適合していない既存コード。該当なしでも明記すること（技術的負債の可視化）。詳細は[common.md](./common.md)を参照 |
| 影響ドキュメント | ○ | このドキュメントが変更されたときに、変更する必要があるドキュメント |
| 関連ドキュメント | △ | 関連する ADR や設計ドキュメント |

### 必須/任意の判断基準

新しいセクションを追加する際は、以下の基準で必須（○）か任意（△）かを判断する:

| 判断基準 | 必須（○） | 任意（△） |
|---------|----------|----------|
| レビュー時に見落とすと問題になるか | ○ | |
| 技術的負債の可視化に必要か | ○ | |
| ADRの文脈理解に必須か | ○ | |
| あれば便利だが無くても理解可能か | | △ |

**例**: 「適用待ちの箇所」は「技術的負債の可視化に必要」という観点から必須（○）と判断

### 関連ドキュメントの選定基準

「関連ドキュメント」セクションには、以下の基準で関連するADRや設計ドキュメントを選定する:

| 関連性の種類 | 説明 | 例 |
|-------------|------|-----|
| 具体化 | このADRのパターンを具体的に実装しているADR | UI/Container分離ADR → ModalDialogBase ADR |
| 基盤 | このADRが前提としているADR | コンポーネント設計ADR → Clean Architecture ADR |
| 同一ドメイン | 同じ技術領域・レイヤーに関するADR | UI層に関する複数のADR |

**チェックリスト**（ADR作成時に確認）:

- [ ] このADRのパターンを既に実装しているコンポーネントのADRはあるか
- [ ] このADRが前提としている設計思想のADRはあるか
- [ ] 同じレイヤー/ドメインに関する既存ADRはあるか
