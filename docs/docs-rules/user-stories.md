# user-stories ドキュメントルール

## ディレクトリ構造

```
docs/user-stories/
├── user-story-{番号}/
│   ├── README.md                 # 必須: ストーリー概要
│   ├── acceptance-criteria.md    # 必須: 受け入れ条件
│   └── prs/                      # 必須: PR計画
│       ├── pr-001-{フェーズ名}.md
│       ├── pr-002-{フェーズ名}.md
│       └── ...
```

## 命名規則

### ディレクトリ名

- 形式: `user-story-{3桁番号}-{機能名}`
- 番号: 001から連番
- 機能名: kebab-case（小文字、ハイフン区切り）
- 例: `user-story-001-rule-toggle`, `user-story-002-batch-delete`

### PRファイル名

- 形式: `pr-{3桁番号}-{フェーズ名}.md`
- 番号: 001から連番（ユーザーストーリー内で連番）
- フェーズ名: kebab-case
- 例: `pr-001-expand.md`, `pr-002-migrate.md`, `pr-003-contract.md`

## 必須ファイル

### README.md

以下のセクションを含む:

| セクション | 必須 | 説明 |
|-----------|------|------|
| ストーリー | ○ | 引用形式でユーザーストーリーを記載 |
| 概要 | ○ | 機能の説明 |
| 関連ドキュメント | ○ | ADR、設計ドキュメントへのリンク表 |
| 開発戦略 | ○ | 採用するパターン（Parallel Changeなど） |
| PR一覧 | ○ | PRへのリンク表（状態を含む） |
| 進捗 | ○ | チェックリスト形式の進捗管理 |
| 受け入れ条件 | ○ | acceptance-criteria.mdへのリンク |

### acceptance-criteria.md

以下のカテゴリで受け入れ条件を記載:

| カテゴリ | 必須 | 説明 |
|---------|------|------|
| 機能要件 | ○ | AC-{番号}形式で機能の受け入れ条件 |
| 非機能要件 | △ | パフォーマンス、アクセシビリティなど |
| 技術要件 | △ | アーキテクチャ、テスト、コード品質 |

- 各条件はチェックリスト形式（`- [ ]`）で記載
- AC番号は連番（AC-1, AC-2, ...）

### prs/pr-XXX-{フェーズ名}.md

以下のセクションを含む:

| セクション | 必須 | 説明 |
|-----------|------|------|
| 概要 | ○ | PRの目的を1-2行で |
| フェーズ | ○ | Parallel Changeのフェーズ名 |
| リスク | ○ | 極低/低/中/高 |
| 前提PR | ○ | 依存するPR（なしの場合は「なし」） |
| 対象ファイル | ○ | 層ごとにファイル一覧表 |
| 完了条件 | ○ | チェックリスト形式 |
| 次のPR | ○ | 次のPRへのリンク（最後の場合は「なし」） |

## 状態表記

### PR状態

| 状態 | 表記 |
|------|------|
| 未着手 | ⬜ 未着手 |
| 作業中 | 🔄 作業中 |
| レビュー中 | 📝 レビュー中 |
| 完了 | ✅ 完了 |

### ファイル状態（PR内）

| 状態 | 表記 |
|------|------|
| 未着手 | ⬜ |
| 完了 | ✅ |

## 進捗管理

- README.mdの「進捗」セクションでマイルストーンを管理
- PRがマージされたらチェックを付ける
- 全PRがマージされたら「機能リリース完了」にチェック

## Parallel Changeパターン使用時

PRは以下のフェーズで分割する:

| フェーズ | 説明 | リスク目安 |
|---------|------|-----------|
| Expand | スケルトン追加、既存コード変更なし | 極低 |
| Migrate | 実装を埋める、テスト追加 | 低 |
| Contract | 統合・有効化、旧コード削除 | 中 |

## コード例の記載

- PR計画ファイル内でのみスケルトン実装例を記載可能
- 設計ドキュメント（docs/design/）ではコード例を記載しない
- スケルトン例は最小限に留める
