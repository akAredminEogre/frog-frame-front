# ドキュメント整合性レビューガイドライン

PRをレビューする際、以下のドキュメント整合性を確認してください。

## 1. ドキュメント同士の整合性

### CLAUDE.md と .clinerules/ の整合性
- CLAUDE.mdに記載されているコマンドが.clinerules/内のワークフローと一致しているか
- コーディング規約の記述が両者で矛盾していないか

### docs/docs-rules/ とドキュメントの整合性
- docs/docs-rules/に定義されたテンプレート・ルールに従ってドキュメントが作成されているか
- docs/design/内のテスト戦略書がdocs/docs-rules/design/05-test-strategy.mdの形式に従っているか

### docs/issue-XXX/ ドキュメントの整合性
- ISSUE.md、PLAN.md、PULL_REQUEST.mdなどの内容が相互に矛盾していないか
- 完了したタスクがPROGRESS-XX.mdに正しく記録されているか

## 2. ドキュメントとコードの整合性

### CLAUDE.md とMakefile/package.jsonの整合性
- CLAUDE.mdに記載されているmakeコマンドがMakefileに存在するか
- npmスクリプトの説明が実際のpackage.jsonと一致しているか

### テスト戦略書とテストコードの整合性
- docs/design/src/内のテスト戦略書で定義されたテストケースが実際のテストファイルに実装されているか
- テストファイルの構成がテスト戦略書の「テストファイル構成」セクションと一致しているか

### コーディング規約とコードの整合性
- .clinerules/01-coding-standards.mdのルールがコードで守られているか
- インポートパスが絶対パス（src/から始まる）になっているか
- Clean Architectureのレイヤー依存関係が守られているか

### ディレクトリ構造ドキュメントの整合性
- docs/DIRECTORY_STRUCTURE.mdが実際のディレクトリ構造と一致しているか
- 新しいディレクトリ/ファイルが追加された場合、ドキュメントの更新が必要か確認

## 3. レビュー時の確認事項

ドキュメントが変更された場合：
- 関連するコードも更新が必要か確認
- 他の関連ドキュメントとの整合性を確認

コードが変更された場合：
- 関連するドキュメントの更新が必要か確認
- 特にpublicなAPIやコマンドの変更はドキュメント更新必須
