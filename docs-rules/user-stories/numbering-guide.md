# ユーザーストーリー番号採番ガイドライン

新しいユーザーストーリーを作成する際の番号採番ルール。

## 採番手順

### 1. 全てのユーザーストーリー番号を検索

以下のコマンドで、リポジトリ内の全ユーザーストーリー番号を取得する:

```bash
find docs -type d -name "user-story-*" 2>/dev/null | sort -t'-' -k3 -n
```

**検索対象ディレクトリ:**

| ディレクトリ | 説明 |
|-------------|------|
| `docs/user-stories/` | 進行中のユーザーストーリー |
| `docs/user-stories/completed/` | 完了したユーザーストーリー |
| `docs/completed/` | 旧形式の完了ディレクトリ（レガシー） |

### 2. Gitログで過去に使用された番号を確認

ディレクトリが削除されていても、過去に使用された番号は再利用しない:

```bash
git log --all --oneline --name-only | grep -oE "user-story-[0-9]+" | sort -u -t'-' -k3 -n
```

### 3. 次の番号を決定

- 検索結果から最大の番号を特定
- 最大番号 + 1 を新しいユーザーストーリー番号とする
- 欠番（例: 010が存在せず009と011がある場合）は埋めない

## 禁止事項

- **過去に使用された番号の再利用禁止**: Gitログに履歴がある番号は使用しない
- **欠番の利用禁止**: 連番でない番号があっても、その間の番号は使用しない

## 理由

- 番号の再利用はGitログや過去のPR/Issueとの混乱を招く
- 欠番は意図的にスキップされた可能性がある（削除、統合など）
- 番号は単調増加を維持することで履歴の追跡が容易になる

## PR作成時の整合性チェック

ユーザーストーリーを含むPRを作成する際は、以下を確認すること:

| チェック項目 | 確認内容 |
|-------------|---------|
| PRタイトル | ユーザーストーリー番号がファイル内容と一致 |
| PR説明文 | ユーザーストーリー番号がファイル内容と一致 |
| コミットメッセージ | ユーザーストーリー番号がファイル内容と一致 |

### 番号修正時の注意

番号を変更した場合（例: 012 → 013）、以下を全て更新すること:

1. ディレクトリ名（`user-story-XXX/`）
2. README.mdのタイトル（`# User Story XXX:`）
3. コミットメッセージ
4. PRタイトル・説明文

## 例

### 現状

```text
docs/user-stories/user-story-002/
docs/user-stories/user-story-007/
docs/user-stories/user-story-009/
docs/user-stories/user-story-011/
docs/user-stories/completed/user-story-001/
docs/completed/user-story-010/
```

Gitログで `user-story-012` の履歴が見つかった場合:

- 使用済み番号: 001, 002, 007, 009, 010, 011, 012
- 次の番号: **013**
