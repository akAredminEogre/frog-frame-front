# 責任の所在を明示する

ルールを記述する際、**誰が・いつ**その責任を負うかを明示すること。

## 具体例

```markdown
## 悪い例（責任が曖昧）

- コードベースに存在することを確認すること

## 良い例（責任が明確）

- **著者が記載時に**コードベースに存在することを確認すること
- **レビュアーがPRレビュー時に**整合性を確認すること
```

## よく使う責任パターン

| 責任者 | タイミング | 例 |
|-------|----------|-----|
| 著者 | 記載時 | ファイル存在確認、パス検証 |
| レビュアー | PRレビュー時 | ルール準拠の確認 |
| CI | マージ時 | 自動テスト |

## 新セクション追加時の既存原則チェック

ドキュメントに新しいセクションやルールを追加する際、**著者が記載時に**同一ドキュメント内の既存原則を確認し、それらに準拠すること。

### チェック項目

- 責任の所在（誰が・いつ）が明示されているか
- 関連する既存ルールとの整合性があるか
- 具体例が必要な場合は記載されているか

```markdown
## 悪い例（既存原則を無視）

3. **外部からの参照更新（必須）**
   - ドキュメントを分割した場合、他ドキュメントからの参照を更新すること
   <!-- 責任者・タイミングが不明確 -->

## 良い例（既存原則に準拠）

3. **外部からの参照更新（必須）**
   - ドキュメントを分割した場合、**著者が記載時に**他ドキュメントからの参照を更新すること
```
