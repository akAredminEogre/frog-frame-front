# 具体例の記載

## 具体例を含める

- 規約やルールを記述する際は、具体例（シナリオ・事例）を1-2個含めること
  - 抽象的なルールだけでは実装時の判断基準が曖昧になる
  - 実際のプロジェクトで発生した事例を具体例として記載すると、チームの理解が深まる
  - **注意**: ここでいう「具体例」とは実装コードではなく、適用シナリオや判断事例を指す

**良い例**: [design-tokens.md](../../../docs/coding-standards/src/frameworks-and-drivers/ui/css-styling/design-tokens.md) の「具体例」セクションでは、削除ボタン用トークンの選定手順やWCAG AA準拠のための色修正事例を記載している

## 良い例/悪い例の対比は1つの差分のみ

「良い例」と「悪い例」を対比させる際は、**差分を1つに限定**すること。複数の差分があると、どの点が修正ポイントか不明確になる。

### 避けるべき対比（悪い書き方）

以下は2つの差分（数値と検証ツール記載）があり、どちらが修正ポイントか不明確な例:

```text
悪い例: /* コントラスト比: 約4.58:1 */
良い例: /* コントラスト比: 約4.52:1 (WebAIM Contrast Checkerで確認) */
→ 問題: 数値も変わり、検証ツールも追加。どちらが本質的な修正？
```

### 推奨する対比（良い書き方）

以下は1つの差分（検証ツール記載の有無）のみで、修正ポイントが明確な例:

```text
悪い例: /* コントラスト比: 約4.52:1 */
良い例: /* コントラスト比: 約4.52:1 (WebAIM Contrast Checkerで確認) */
→ 明確: 検証ツール記載の追加が修正ポイント
```
