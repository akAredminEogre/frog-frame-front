# ドキュメントリファクタリング時の同期ルール

ドキュメントのファイル名変更・ファイル分割・ファイル統合を行った場合の同期ルール。

## 適用範囲

以下の操作を行った場合に適用：

- ファイル名の変更
- 1つのファイルを複数ファイルに分割
- 複数ファイルを1つに統合
- ファイルの配置先ディレクトリ変更

## 必須チェックリスト

### 1. 参照元の更新

- [ ] `grep -r "旧ファイル名" docs/` で参照元を検索
- [ ] `grep -r "旧ファイル名" docs-rules/` で参照元を検索
- [ ] `grep -r "旧ファイル名" CLAUDE.md` で参照元を検索
- [ ] `grep -r "旧ファイル名" .AI/` で参照元を検索
- [ ] 検出されたすべての参照を新しいパスに更新

### 2. 相互参照の更新

- [ ] 変更したファイル内の相対パスリンクが正しいか確認
- [ ] 分割した場合、分割後のファイル間で相互参照が正しいか確認

### 3. 目次・インデックスの更新

- [ ] 該当ディレクトリの `index.md` があれば更新
- [ ] 上位ディレクトリの目次に影響があれば更新

### 4. 内容の完全性確認

- [ ] 分割の場合：元ファイルの内容がすべて分割先に含まれているか
- [ ] 統合の場合：統合元のすべての内容が統合先に含まれているか
- [ ] 削除された内容がないか確認

## 検索コマンド例

```bash
# 旧ファイル名への参照を検索
grep -r "07-e2e-test-strategy\.md" docs/ docs-rules/ CLAUDE.md .AI/

# Markdownリンク形式での参照を検索
grep -r "\[.*\](.*旧ファイル名.*)" docs/ docs-rules/
```

## 分割時の追加ルール

ファイルを複数に分割する場合：

1. **分割の観点を明確化**: なぜ分割するのか（形式/動作、概念/手順など）を明確にする
2. **相互参照を追加**: 分割後のファイル間で「参考」セクションを設け、関連ファイルをリンク
3. **元ファイルの削除**: 分割後は元ファイルを削除し、参照をすべて更新
4. **ディレクトリリンクの対応**: 新しいディレクトリへの参照を更新する際、以下のいずれかを選択：
   - ディレクトリに `index.md` を作成してディレクトリパスでリンク
   - 具体的なファイル（例：`format-guideline.md`）にリンク

### ディレクトリリンクのルール

GitHubなどのMarkdownレンダラでは、`index.md`や`README.md`がないディレクトリへのリンクは正常に表示されない。

```markdown
❌ 悪い例：index.mdがないディレクトリへのリンク
[07-e2e-test-strategy/](../design/07-e2e-test-strategy/)

✅ 良い例：具体的なファイルへのリンク
[07-e2e-test-strategy/format-guideline.md](../design/07-e2e-test-strategy/format-guideline.md)

✅ 良い例：index.mdがあるディレクトリへのリンク
[07-e2e-test-strategy/](../design/07-e2e-test-strategy/)  # index.mdが存在する場合
```

## 統合時の追加ルール

ファイルを統合する場合：

1. **重複内容の整理**: 統合元で重複している内容は1つにまとめる
2. **セクション構成の見直し**: 統合後のセクション構成が論理的か確認
3. **統合元ファイルの削除**: 統合後は元ファイルをすべて削除
