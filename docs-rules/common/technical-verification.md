# 推奨事項と技術的検証

## 推奨事項の理由記述

コーディング規約で特定の実装方法を推奨（または非推奨）とする場合、以下を必ず記載すること:

1. **理由（なぜその方法を推奨/非推奨とするか）**
   - 技術的な背景
   - 代替案との比較で優れている/劣っている点

2. **問題が発生するケース**（非推奨の場合）
   - 非推奨の方法を使った場合に何が起きるか
   - 具体的な環境や条件（例: テスト環境、特定のライブラリとの組み合わせ）

### 悪い例

```text
- 初期フォーカス設定（手動useEffect推奨、テスト環境との互換性のため）
```

→ 「テスト環境との互換性」だけでは、なぜ互換性の問題が生じるか不明

### 良い例

```text
- 初期フォーカス設定
  - 手動useEffectを推奨（FocusScopeのautoFocusは使用しない）
  - 理由: autoFocusはReact Ariaの内部タイミングでフォーカスを設定するため、
    テスト環境（happy-dom）でのライフサイクルと競合する可能性がある
```

→ 技術的背景と問題が発生する条件が明確

## 数値・技術的主張の検証

ドキュメントに数値や技術的な主張を記載する際は、**記載前に検証ツールで確認**すること。

### 対象となる記述

| 種類 | 例 | 検証方法 |
|------|-----|---------|
| 色コントラスト比 | 「コントラスト比は約5.47:1」 | WebAIM Contrast Checker等で計算 |
| パフォーマンス値 | 「レンダリング時間は約100ms」 | 実測またはプロファイラで確認 |
| ファイルサイズ | 「バンドルサイズは約50KB」 | ビルド出力で確認 |
| バージョン番号 | 「React 18以降で対応」 | 公式ドキュメントで確認 |

### ルール

1. **検証責任**: 著者が記載時に検証する
2. **検証ツールの明記（必須）**: どのツール/方法で検証したかを必ず記載する（省略不可）
3. **概算表記**: 検証済みでも「約」を付けて表記することで、微小な変動を許容する

### 具体例

#### Markdownドキュメントの場合

```markdown
## 悪い例（未検証の数値）

コントラスト比は約5.14:1でWCAG AA基準をクリア。

## 良い例（検証済みの数値）

コントラスト比は約5.47:1でWCAG AA基準(4.5:1)をクリア。
<!-- WebAIM Contrast Checkerで検証: #c53030 vs #ffffff -->
```

#### CSSコメントの場合

```css
/* 悪い例（検証ツール未記載） */
/* WCAG AA準拠: #2f855a + #fff = 約4.52:1 (基準4.5:1以上) */

/* 良い例（検証ツール明記） */
/* WCAG AA準拠: #2f855a + #fff = 約4.52:1 (基準4.5:1以上, WebAIM Contrast Checkerで確認) */
```

### 既存数値の引用

他のドキュメントやコードから数値を引用する場合も、**著者が記載時に**引用元が正確か確認すること。古い情報や誤った情報が伝播することを防ぐ。
