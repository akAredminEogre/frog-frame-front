# アローダイアグラム規約

コンポーネント間の依存関係・データフローを ASCII Art 形式で図示するための規約。

## 概要

アローダイアグラムは、クリーンアーキテクチャにおける依存の方向と、コンポーネント間のデータフローを
視覚的に示す設計ドキュメントである。シーケンス図 (02-sequence.puml) が「時系列フロー」を示すのに対し、
アローダイアグラムは「静的な依存関係・データの流れ方向」を示す。

## 記法ルール

### 矢印の種類と意味

| 記法 | 意味 |
|------|------|
| `-->` | 依存 (依存元 --> 依存先) |
| `==>` | データフロー (データの流れる方向) |
| `<--` | 逆依存 (原則禁止、例外のみ) |
| `---` | 関連 (依存なし、参照のみ) |

### 必須凡例

図の直後に凡例ブロックを必ず記載すること。

```text
凡例:
  --> 依存の方向 (外 -> 内のみ許可)
  ==> データの流れる方向
```

### 許可スコープ

- **依存の方向**: 外層 → 内層のみ許可 (Clean Architecture 原則)
  - Presentation → Application → Domain
  - Infrastructure → Application → Domain
- **内 → 外の依存**: インターフェース (Port) 経由でのみ許可
- **横断的依存**: 同一層内の依存は最小限に留める

## 必須要素

アローダイアグラムファイルには以下を必ず含めること:

1. **コンポーネント一覧**: 図示するコンポーネントと役割の簡潔な説明
2. **ASCII Art 図**: 依存関係・データフロー図本体
3. **凡例**: 矢印の意味説明
4. **補足**: 設計上の注意事項 (省略可)

## オプション要素

- レイヤー境界の明示 (層ごとに区切り線を引く)
- データ型の注記 (`// DTO`, `// Entity` など)

## サンプル図

### サンプル 1: 機能単体のデータフロー

```text
[UI Component]
     |
     | (ユーザー操作イベント)
     v
[UseCase: ToggleRuleActive]
     |
     | (Rule ID)
     v
[Repository Interface]  <-- (DI)  [RepositoryImpl]
                                        |
                                        | (DB / Storage)
                                        v
                                   [DataStore]

凡例:
  --> 依存の方向 (外 -> 内のみ許可)
  <-- 依存注入 (DI)
  (text) データ/イベントの内容
```

### サンプル 2: 複数コンポーネントの依存マップ

```text
Presentation Layer
+---------------------------------+
| RuleListPage                    |
|   --> RuleListViewModel         |
+---------------------------------+
          |
          | --> (interface)
          v
Application Layer
+---------------------------------+
| RuleListUseCase                 |
|   --> RuleRepository (interface)|
+---------------------------------+
          |
          | <-- (DI)
          v
Infrastructure Layer
+---------------------------------+
| RuleRepositoryImpl              |
|   --> ChromeStorageAdapter      |
+---------------------------------+

凡例:
  --> 依存の方向
  <-- 依存注入 (DI)
```
